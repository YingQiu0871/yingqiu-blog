This post doubles as documentation. Everything below is written with the same features available to any article.

## The five sections

Every post belongs to one of five stable sections. Sections are the long-lived structure of the blog — they do not grow as new posts appear; topics belong to **tags** instead.

| `category`  | Name        | URL                    | What goes there                       |
| ----------- | ----------- | ---------------------- | ------------------------------------- |
| `fuguang`   | Moments     | `/moments/`            | Daily life, travels, moods, now       |
| `jiujian`   | Old Letters | `/old-letters/`        | Writings from childhood and school    |
| `liusheng`  | Music       | `/music/`              | Songs, playlists, memories of music   |
| `qiushu`    | Quest       | `/quest/`              | Study, research, labs, the road ahead |
| `shiju`     | Quotes      | `/quotes/`             | Excerpts, poems, lines kept from reading |

Chinese URLs mirror them under `/zh/` (e.g. `/zh/fuguang/`).

## Where files live

Posts are MDX files under `content/blog/`, one file per language:

```text
content/blog/
├── en/
│   ├── hello-yingqiu.mdx
│   └── writing-a-post.mdx
└── zh/
    ├── hello-yingqiu.mdx
    └── writing-a-post.mdx
```

The filename (without `.mdx`) is the slug — it becomes the URL: `/posts/writing-a-post/` (English) or `/zh/posts/writing-a-post/` (Chinese). The two language versions pair up by using the same filename.

## Front matter

Every file starts with YAML front matter:

```yaml
---
title: 'The post title'
description: 'One sentence shown in listings, RSS, and search results.'
date: 2026-08-12            # required: when it is published/re-edited here
updated: 2026-08-14         # optional
category: fuguang           # one of the five ids above; defaults to fuguang
tags: [Guide, MDX]          # topics; comma-separated string also works
cover: /images/covers/x.jpg # optional: card cover image
draft: true                 # optional; hides the post from listings and RSS
# —— Old Letters (jiujian) ——
originalDate: 2019-06       # when it was originally written: 2019 / 2019-06 / 2019-06-15
rereadNote: 'Rereading it years later…'  # short note shown before the body
# —— Quotes (shiju) ——
quote: 'The quoted text'
quoteSource: 'Book · Author'
# —— Music (liusheng) ——
music:
  - title: Song title
    artist: Artist
    url: https://music.163.com/#/song?id=123   # optional external link
    note: A memory attached to this song       # optional
---
```

| Field          | Required | Purpose                                              |
| -------------- | -------- | ---------------------------------------------------- |
| `title`        | yes      | Post title                                           |
| `description`  | yes      | Summary for cards, RSS, and metadata                 |
| `date`         | yes      | `YYYY-MM-DD`, sorted newest first                    |
| `updated`      | no       | Shown next to the date when present                  |
| `category`     | no       | Section id; defaults to `fuguang`                    |
| `tags`         | no       | Topics — any number, any granularity                 |
| `cover`        | no       | Card cover image path                                |
| `draft`        | no       | Set `true` to hide a post until it is ready          |
| `originalDate` | no       | 旧笺 only: original writing time                     |
| `rereadNote`   | no       | 旧笺 only: "years later" note before the body        |
| `quote`        | no       | 拾句 only: the quoted text itself                    |
| `quoteSource`  | no       | 拾句 only: source of the quote                       |
| `music`        | no       | 流声 only: track list rendered as a glass panel      |

Old Letters sort by `originalDate` (childhood first); everything else sorts by `date`, newest first. Drafts are ignored by listings, RSS, and the sitemap, but you can preview them locally with `npm run dev`.

### Code blocks

Fenced code with a language gets syntax highlighting:

```ts
export function getPosts(lang: string): BlogPost[] {
  return fs
    .readdirSync(path.join(BLOG_DIR, lang))
    .filter((file) => file.endsWith('.mdx'))
    .map((file) => readPost(lang, file.replace(/\.mdx$/, '')))
    .filter((post): post is BlogPost => post !== null && !post.draft)
    .sort((a, b) => b.date.localeCompare(a.date));
}
```

### Images

Put images in `public/images/` and reference them with an absolute path:

```md
![Alt text](/images/example.png)
```

### Music embeds

In 流声 posts you can embed Spotify / Apple Music / 网易云 players directly in MDX:

```mdx
<Embed src="https://open.spotify.com/embed/track/4cOdK2wGLETKBW3PvgPWqT" height="152" />
```

## Bilingual posts

Write both `content/blog/en/<slug>.mdx` and `content/blog/zh/<slug>.mdx`. If a language version is missing, readers see a friendly panel linking to the existing one. There is no requirement to publish both at once — an English post alone simply shows the fallback panel on the Chinese route.

## Publishing

Commit to `main` and push. The GitHub Actions workflow builds the site with `NEXT_PUBLIC_SITE_URL`, regenerates the RSS feed, and syncs `out/` to `/var/www/blog` on the server — the full setup is documented in the portfolio repository's `deploy/DEPLOY.md`.
